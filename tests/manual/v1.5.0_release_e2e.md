# v1.5.0 release walkthrough: fresh dev container

The last check before tagging v1.5.0. Start from a freshly built dev container with no pipelines
installed and follow one researcher's path: install pipelines from the viewer, run a job, review
it, run a batch, export. It covers spec 011's SC-001 run
([`pipeline_readiness_e2e.md`](pipeline_readiness_e2e.md)) plus everything else v1.5.0 ships.

Tick each box as you go. Put anything that fails under **Findings** at the bottom, with the step
number, what you saw, and any log lines.

---

## 0. Before you start (on the host)

- [ ] **Ollama** is running on the host (`ollama serve`) with a vision model pulled, e.g.
      `ollama pull qwen2.5vl:7b`.
- [ ] **Hugging Face token** in `.env` (`HUGGINGFACE_TOKEN=hf_...`). The account has accepted the
      licences for [pyannote/speaker-diarization-3.1](https://huggingface.co/pyannote/speaker-diarization-3.1)
      and [pyannote/segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0).
- [ ] **Test videos** in a folder the container can see, e.g. `~/va-e2e/` in the workspace:
  - one **H.264** clip of 10–30 s with speech and a visible face (the main test video);
  - one **H.265/HEVC** clip (for the codec message);
  - a folder of **3–5 short clips** (for the batch and folder-ingest tests).
- [ ] Note the **browser** and version you'll use. Chrome or Edge on Windows is the reference.

## 1. Reset to a clean state

The workspace is bind-mounted, so the environment, database, results and model downloads survive a
container rebuild. Move them aside; don't delete them, so you can restore them afterwards.

```bash
mkdir -p ../va-before-e2e
mv .venv videoannotator.db storage logs ../va-before-e2e/ 2>/dev/null
mv models ../va-before-e2e/ 2>/dev/null   # optional: also re-tests the model downloads (slow)
```

Keep `.env`: it holds the token.

- [ ] Done. `git status` is clean, or only shows changes you expect.

## 2. Rebuild the container

In VS Code: **Dev Containers: Rebuild Container**. Wait for `postCreateCommand` to finish
(`uv sync --inexact --extra dev`, hadolint, pre-commit).

- [ ] `uv run videoannotator version` prints `VideoAnnotator v1.5.0` and the InfantLab repo URL.
- [ ] Core only: `uv run python -c "import torch"` **fails** with `ModuleNotFoundError`.
- [ ] `echo $OLLAMA_BASE_URL` prints `http://host.docker.internal:11434`, not `http`.
- [ ] `curl -s $OLLAMA_BASE_URL/api/version` returns JSON.
- [ ] `echo "${HUGGINGFACE_TOKEN:-(blank: .env will supply it)}"` shows one or the other, not an
      error.
- [ ] `ffmpeg -version` works.
- [ ] `nvidia-smi` shows the GPU (GPU container only).

## 3. Automated checks (optional, about 10 minutes)

- [ ] `uv run ruff check .` is clean.
- [ ] `uv run pytest tests/unit -q` passes. With no extras installed many pipeline tests skip;
      none should fail.

## 4. First start

```bash
scripts/start_server.sh
```

- [ ] First-time setup asks for an admin email and username, creates `videoannotator.db`, and prints
      an API key and a "Connect the viewer with one click" link.
- [ ] Startup log: **each line appears once**. No `INFO:name:message` duplicates and no tracebacks.
- [ ] The log shows `Uvicorn running on http://0.0.0.0:18011`. (No "Torch warmup" line yet:
      torch isn't installed.)
- [ ] Open the one-click link. The viewer opens at `/viewer`, already connected.
- [ ] `/viewer/settings` shows the server as connected and you as **admin**.

## 5. Discover pipelines (viewer only from here on)

Go to **Create Job** (`/viewer/jobs/new`), add the main test video, then **Select Pipelines**.

- [ ] Every shipped pipeline is listed. No "Stub" pipeline.
- [ ] Face, audio, scene, person, OpenFace 3 and LAION show **Not installed**, each with an
      Install button, the group name and an approximate size.
- [ ] VLM Frame Annotation shows **Not installed** (llm group).
- [ ] Nothing asks you to open a terminal.

## 6. Install pipelines from the viewer

Install one group at a time, in this order. After each: it becomes selectable by itself
("Installed. Loading…" then a checkbox), **or** a **Server restart needed** banner appears. Click
**Restart server**; within about 30 s the page recovers and the pipeline is selectable.

- [ ] **scene** (Scene Detection)
- [ ] **face** (Face Analysis, DeepFace). While it's installing, **reload the page**: the card
      still shows **Installing**. Known, not a blocker: the wizard itself resets to "Choose videos".
- [ ] **person** (Person Tracking)
- [ ] **audio** (Speech Recognition, Speaker Diarization, Audio Processing). Speaker Diarization
      becomes **selectable**, with licence notes linking both pyannote models. If it says
      "Needs setup… HUGGINGFACE_TOKEN", the token didn't reach the server: stop and note it.
- [ ] **llm** (VLM Frame Annotation). Becomes **selectable** with Ollama reachable. If it says
      "Ollama isn't reachable at …", check the URL it names.
- [ ] **face-openface3** (OpenFace 3). Installs `openface-test` **0.1.13**; the install log must
      not show `Building pillow==9.4.0`.
- [ ] Optional, large: **face-laion**, **audio-laion** (LAION voice downloads 16 GB or more).
- [ ] Afterwards, `/viewer/settings` (or `GET /api/v1/pipelines`) shows no pipeline still needing
      a restart.

## 7. One video, every pipeline

Main test video, select every installed pipeline, VLM with a simple prompt (e.g. "Is a baby
visible? Answer yes or no."), submit.

- [ ] The job appears in **Jobs** and moves through queued → running → completed. The first
      run may be slow while models download, and the UI says so; it doesn't look stuck.
- [ ] Every pipeline completes. If any fail, the job shows **completed with errors** and the
      reason. `face_openface3_embedding` in particular must **not** fail with "not installed".
- [ ] **Open results**: the video plays, and the timeline and overlays show:
  - [ ] face boxes and emotions;
  - [ ] person boxes or pose;
  - [ ] speech transcript (subtitles);
  - [ ] speaker turns (diarization);
  - [ ] scene boundaries;
  - [ ] VLM labels per sampled frame;
  - [ ] OpenFace 3 output.
- [ ] Seeking and play/pause keep the overlays in sync.
- [ ] **Download** the job's artifacts: the zip contains the video, per-pipeline outputs and the log.

## 8. Batch and folder ingest

- [ ] **Upload batch**: Create Job with the 3–5 clip folder's files, one or two light pipelines
      (scene + face), a batch name. It's one batch in **Batches** (`/viewer/batches`) with
      real progress.
- [ ] Reload the page, or open it in another browser: the batch is still there as one item.
- [ ] **Cancel** one queued job; **Retry** it; it completes.
- [ ] **Folder ingest**: Create Job → Folder → pick the same folder on the server. Every video
      becomes a job in one batch, and nothing is copied (check the `storage/` size).
- [ ] Deleting one ingested job leaves the original video in place.

## 9. Library, datasets, presets

- [ ] `/viewer/library`: pick a library folder, or install the demo datasets. Videos are listed.
- [ ] In Create Job → Select Pipelines, **Save selection as preset**, then start a new job and
      **Load** it: the pipelines and settings are applied, and pipelines that aren't ready are
      left out with a note saying why.
- [ ] `/viewer/datasets`: note what it shows. The v1.6.0 roadmap expects a placeholder here.

## 10. Codec message (HEVC)

Open results for a job run on the HEVC clip, in **both Chrome and Edge** if you have them.

- [ ] Annotations and timeline work in both.
- [ ] **Chrome** (hardware acceleration on): the video plays, and no message.
- [ ] **Edge**: on the reference machine it fails to decode this HEVC file even with HEVC Video
      Extensions installed. The message "This browser couldn't show the picture of this video
      (H.265/HEVC, according to the file)" appears; **Details** shows the browser's own error
      (`MEDIA_ERR_DECODE: PipelineStatus::PIPELINE_ERROR_DISCONNECTED`).
- [ ] Open an H.264 job straight after: it plays, with no message left over.

(Diagnosis and the evidence: [`viewer-handoff-hevc.md`](../../specs/011-pipeline-readiness/viewer-handoff-hevc.md#handback-2026-09-26-video-annotation-viewer).
An `hvc1` remux makes no difference.)

## 11. CLI (same server, second terminal)

- [ ] `uv run videoannotator pipelines list` shows the installed pipelines as available.
- [ ] `uv run videoannotator job submit <video> --pipelines scene_detection` returns a job ID, and
      the job appears in the viewer's job list.
- [ ] `uv run videoannotator job status <id>` reports it completed.

## 12. Edge cases

- [ ] **Ollama down**: stop Ollama on the host. The VLM card shows **Needs setup**, naming
      `http://host.docker.internal:11434`. Start it, click **Check again**: selectable.
- [ ] **Non-admin key**: `uv run videoannotator generate-token --no-admin`, connect with it. Cards
      show their state; Install and Restart are replaced by an explanation.
- [ ] **`--reload`**: start the server with `--reload`, then click **Restart server** after an
      install that asks for it. The banner shows how to restart manually.
- [ ] **Restart persistence**: stop and start the server. Jobs, batches and results are still there.
- [ ] **Rebuild persistence**: rebuild the container once more. Installed pipelines are still
      installed (`--inexact` keeps them), and the jobs are still there.

## 13. Afterwards

- [ ] Restore your previous state if you want it back:
      `mv ../va-before-e2e/* .` (after moving the new `.venv`, db, storage and logs aside).
- [ ] If everything passed: in `CHANGELOG.md`, fold `[Unreleased]` into `[1.5.0]`, set the date,
      tick SC-001 in `docs/development/roadmap_v1.5.0.md`, tag `v1.5.0`.
